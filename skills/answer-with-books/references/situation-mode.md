# 具体处境模式

## 目的

用于用户不是提出抽象问题，而是讲述一段真实经历、情绪或现实困境的情况。先把处境拆清楚，再判断哪些书真正相关。不要把它变成心理诊断、咨询话术或替用户做决定。

## 1. 还原事实主线

只记录用户明确提供的内容：

- 发生了什么；
- 涉及哪些人和关系；
- 目前持续了多久；
- 用户已经尝试过什么；
- 哪些现实条件暂时不能改变；
- 用户正在考虑或回避什么决定。

不得补写动机、经历、对方意图或因果关系。

## 2. 建立处境地图

在后台区分以下层次：

1. **事实**：可从叙述直接确认的情况；
2. **解释**：用户目前如何说明这些事实，例如“因为环境不适合，所以我不开心”；
3. **情绪功能**：焦虑、愤怒、委屈或麻木可能在保护什么、提醒什么；只写为待验证假设；
4. **核心需要或身份威胁**：主动权、认可、安全、归属、意义、能力感或边界中，哪些可能受到影响；
5. **现实限制**：收入、家庭责任、时间、健康、关系成本或不可逆风险；
6. **真正待回答的问题**：用户需要理解处境、度过阶段、判断去留，还是设计下一步行动。

保留多种可能解释，不把所有问题归因于环境，也不把现实伤害全部解释成用户心态。

## 3. 判断是否需要澄清

只有缺失信息会显著改变选书或回答方向时，提出一个问题。例如：

- 用户更想判断是否离开，还是先改善当前状态；
- 当前危险是否需要立即处理，而不是继续阅读；
- 主要困扰是现实资源受限，还是情绪和身份冲突。

如果可以在不确定性下安全继续，就说明哪些理解是暂定的，不强行追问。

## 4. 为处境分配书籍角色

选择 2–3 本书分别回应不同层面。可使用的角色包括：

- **理解处境**：重新命名用户正在经历的转换、冲突或失落；
- **改变视角**：挑战已经锁死用户的因果解释或二元选择；
- **恢复主动权**：帮助发现现实限制内仍可选择的部分；
- **支持决策**：提供判断去留、边界或风险的框架；
- **行动实验**：把抽象方向转成低风险、可逆的小规模尝试。

角色不是固定席位。只保留与当前处境真正相关的书。若两本书处理的是同一层，删除较弱的一本。

## 5. 写作边界

- 先承认现实处境与感受，不用“都是你的认知造成的”否定外部问题；
- 使用“可能”“一个值得检查的解释是”等语言区分推测与事实；
- 不给用户贴人格、依恋或精神疾病标签；
- 不把一本书包装成治疗方案；
- 不因为某个观点有启发，就要求用户立即采取不可逆行动；
- 行动建议优先采用记录、对话、观察、试验和信息收集；
- 用户出现自伤、他伤、严重失能或现实安全风险时，优先处理安全与专业支持，书籍只作补充。

## 6. 输出检查

提交前确认：

1. 开头是否让用户感到自己的具体处境被准确理解；
2. 是否区分了事实、解释和待验证假设；
3. 每本书是否回应不同层面；
4. 每篇回答是否至少回到一个用户明确提供的细节；
5. 是否保留现实限制，没有用心态建议覆盖现实问题；
6. 是否把最终判断权留给用户。
