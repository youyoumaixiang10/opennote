# 以书作答

## 目标

让 2–3 本真正相关、彼此互补的书分别回答同一个问题。保留每本书自身的立场和论证，不把它们压成一句共同结论，也不为每本书生成新的 Skill。

默认使用与用户相同的语言。把蒸馏、核验和边界判断留在后台；前台保持自然、克制、有层次。

## 工作流

### 1. 理解问题

先判断输入属于哪种模式：

- **开放问题模式**：用户提出哲学、人生、关系、成长或价值问题；
- **具体处境模式**：用户讲述一段真实经历，其中包含情绪、判断、现实限制或待做的决定。

开放问题模式下，识别表面问题背后的 2–4 个核心张力，例如：

- 意义来自发现还是创造；
- 幸福是感受还是生活方式；
- 个人选择与现实责任如何冲突；
- 接受处境与改变处境如何区分。

具体处境模式下，完整阅读 [situation-mode.md](references/situation-mode.md)，先区分事实、用户解释、情绪功能、核心需要、现实限制和真正待回答的问题，再进入选书。不要只抓取叙述中的一个关键词。

问题本身清楚时直接继续，不为开放而开放的问题强行追问。只有不同理解会显著改变选书时，才提出一个必要的澄清问题。

### 2. 推荐 2–3 本互补的书

按以下顺序选择：

1. 书是否直接处理这个问题，而不只是标题相关；
2. 每本书能否提供不同但有价值的回答；
3. 是否能获得足够可靠的文本或权威材料；
4. 这些书放在一起是否形成有意义的张力、分工或对照。

优先选择 3 本；只有 2 本真正合适时就推荐 2 本。不要为了数量加入弱相关书籍，不要推荐 3 本观点高度重复的书，也不要把畅销或知名当作相关性的替代。

具体处境模式下，让不同书籍分别处理处境中的不同层面，例如身份转换、情绪与主动权、现实决策或行动实验。不要推荐三本都只会泛泛劝用户“调整心态”的书。

### 3. 做问题导向的轻量蒸馏

完整阅读 [distillation-method.md](references/distillation-method.md)，再处理每本书。

围绕当前问题，从每本书提取：

- 一个核心回答；
- 3–5 个相互关联的关键观点；
- 作者从起点到结论的论证路径；
- 最深、最反直觉或最容易被误解的一层；
- 必要的适用边界。

具体处境模式下，再检查这些观点如何解释用户的真实处境、能改变哪一层理解，以及哪些事实仍然不足以判断。不得为了贴合用户而把书中没有的结论强加给作者。

让这些内容成为当次回答的临时依据，不创建永久书籍 Skill，不输出蒸馏卡，不把内部字段暴露给用户。

### 4. 核验来源

能访问用户提供的原书、合法公开文本或可靠预览时，优先使用这些材料。需要精确引用、版本信息或出处时进行检索核验。

只引用已经核对的文字，并把出处放在引文或相关表述附近。无法核对时，省略引文并使用准确的观点转述；不得根据记忆伪造原文、页码或章节。

### 5. 写出每本书的独立回答

完整阅读 [output-contract.md](references/output-contract.md)，并严格遵循其前台结构。

把每本书写成一篇短小但完整的思想回答，而不是：

- 一句金句加一段解释；
- “观点一、观点二、观点三”的分析报告；
- 全书摘要；
- 模仿作者口吻的角色扮演。

让多个观点自然形成“起点 → 展开 → 转折 → 回到用户问题”的路径。保持每本书的差异，不在书籍段落中偷渡其他书的结论。

具体处境模式下，先用简短自然段回应并拆开用户的处境，再推荐书籍。每本书都要明确回到用户叙述中的一个具体矛盾、限制或选择，而不是只讲抽象道理。

### 6. 开放式收束

结尾只指出 2–3 本书分别把问题带向了哪里，再用一个自然的问题把选择权交还给读者。

默认不要生成“综合结论”或“最终答案”。只有用户明确要求“帮我综合判断”“你认为哪一个更适合我”或类似请求时，才增加综合判断，并说明其依据。

## 特殊情况

- **缺少可核验原文**：明确说明本次基于已有知识做观点概括，不使用引号冒充原文。
- **小说、散文、诗歌**：提炼处境、隐喻、价值冲突与生命体验，不强行转成执行步骤。
- **医学、法律、财务或现实安全问题**：把书籍视角作为补充，不替代最新的权威信息或专业帮助。
- **用户已经指定书籍**：保留其选择；只有明显不相关或存在错误归属时才说明问题。
- **用户要求简短**：缩短每本书篇幅，但仍保留至少两层相关思想，避免退化成金句卡片。
- **具体处境信息不足**：只提出会显著改变选书或判断的一个澄清问题；其他不确定处使用“可能”“需要进一步确认”等表述，不补写用户没有提供的事实。

## 质量红线

- 不把模型记忆包装成已核验原文。
- 不使用来源不明的名人名言网站作为关键引文依据。
- 不让三本书重复表达同一个观点。
- 不为丰富而堆砌无关概念或长篇书摘。
- 不把后台方法名称、验证字段或蒸馏过程写给用户。
- 不强行调和分歧，不用 AI 替读者完成价值选择。
- 不把假设写成事实，不给用户贴心理标签，不把现实问题全部内化为个人心态问题。
