## 澄清假设

把输入拆为四类：

| 类别 | 定义 | 处理方式 |
|---|---|---|
| 事实 | 用户提供或已经核验的信息 | 作为当前依据，同时注意时间与范围 |
| 解释 | 用户对事实含义的理解 | 与替代解释比较 |
| 假设 | 没有明确证据但分析依赖的前提 | 标记并测试其影响 |
| 未知 | 尚未提供或无法确认的信息 | 判断是否会改变结论 |

只有某个未知会改变问题定义、首选方案或风险等级时才追问。一次只问一个最关键的问题，并说明为什么它会改变答案。其余未知使用明确假设处理。

## 因果拆解

### 何时使用

当用户问“为什么”、问题由多因素共同造成、表面症状可能不是根因，或行动取决于因果判断时使用。

### 方法

1. 定义结果指标和变化发生的时间、范围与分布。
2. 区分症状、直接原因、促成因素、硬约束和反馈回路。
3. 至少保留一个能解释同一现象的替代假设。
4. 寻找能区分不同假设的证据，而不是为首个解释收集支持材料。
5. 先验证贡献最大的 1–2 个原因，再设计行动。

相关性、时间先后和管理层判断都不能单独证明因果关系。

## 现实校准

### 何时使用

当用户表达的目标与可观察的时间投入、资源配置、重复选择或行动结果明显不一致时使用。

### 方法

- 并列呈现“用户说重要的事”和“行为实际优先的事”。
- 检查差距来自能力、资源、激励、冲突目标、环境约束还是信息不足。
- 只描述证据支持的不一致，不推断隐藏动机，不断言用户“在欺骗自己”。
- 把结论转化为可验证的小行动，而不是人格评价。

## 红队检验

形成初步结论后检查：

1. 哪项新事实最可能推翻它？
2. 当前最脆弱的假设是什么？
3. 失败会以什么早期信号出现？
4. 是否存在重大、不可逆或由他人承担的代价？
5. 如果反方是对的，当前分析遗漏了什么？

红队的目的不是制造“双方都有道理”的平衡感，而是提高最终判断的可靠性。检验完成后返回结论：维持、修改或撤回，并说明原因。

## 示例：团队业绩下降

问题：连续三个季度业绩下降，管理层认为员工执行力不行，准备加强考核。

1. 澄清假设：业绩下降是事实；“执行力不行”是尚未证明的解释。
2. 因果拆解：按市场机会、线索、转化、客单价、复购、产品和交付拆分，查看下降从何时、何处开始。
3. 替代解释：需求变化、产品竞争力、定价、线索质量、流程阻塞和资源配置都可能产生相同症状。
4. 区分证据：若同等市场、产品和资源下只有部分团队的关键动作与业绩同步下降，执行问题才更可信；若所有区域同时下降，优先检查共同上游因素。
5. 红队检查加强考核可能造成的短期行为、数据美化和人才流失。
6. 判断：先用数据和访谈验证贡献最大的原因，再决定是否把考核作为局部措施；不要把未经验证的管理解释直接变成全员方案。
