# 问题导向的轻量蒸馏

## 目的

吸收“把长内容变成可调用方法”的核心思想，但只为当前问题临时蒸馏相关内容。不要为每本书创建新的 Skill、索引仓库或永久知识包。

## 1. 建立问题地图

在后台写出：

- 用户真正问的是什么；
- 问题中包含哪些互相拉扯的价值或假设；
- 哪类书能够提供不同层次的回答；
- 用户需要的是理解、安慰、判断、行动，还是保留开放性。

开放的人生或哲学问题无需被缩成单一“真实意图”。允许问题本身保留多义性。

如果用户提供的是一段具体经历，先按 [situation-mode.md](situation-mode.md) 建立处境地图。书籍选择必须回应处境地图，而不是只匹配叙述中的主题词。

## 2. 选择互补书籍

给候选书按四项判断：

| 判断项 | 合格标准 |
|---|---|
| 直接相关 | 书中持续处理该问题，而非偶然提到 |
| 独立回答 | 它能给出一句与其他候选不同的核心回答 |
| 思想厚度 | 至少能提取 3 个彼此相关的观点 |
| 证据条件 | 能找到原书、合法公开文本、可靠预览或权威研究材料 |

排除只有知名度、没有直接解释力的书。若两本书的回答可以互换，只保留论证更直接、证据更充分的一本。

不要机械追求地域、时代或流派多样性；只在它确实改善问题理解时选择不同传统。

## 3. 为每本书提取思想链

对每本书建立一个不对用户展示的临时结构：

1. **起点**：作者如何重新定义或拆解这个问题；
2. **核心回答**：如果压缩成一句话，作者会把答案放在哪里；
3. **关键观点**：选择 3–5 个真正支撑核心回答的观点；
4. **关系**：这些观点是并列、递进、转折，还是互相限制；
5. **深层转折**：书中最反直觉、最容易被误读或最能改变理解的一层；
6. **边界**：这本书没有回答什么，或者什么情况下不应照搬。

只有能形成思想链的观点才进入正文。单独漂亮但无法支撑回答的句子不进入。

## 4. 核验强度

### 原文模式

存在用户提供的文本、公版文本、出版社或作者材料、Google Books 等可靠预览时：

- 核对引文原句；
- 记录章节、页码、段落或稳定链接；
- 优先读取引文前后文；
- 区分作者观点、译者措辞和自己的解释。

每本书通常只保留 1–2 处关键短引文。默认每个来源引用不超过 25 个英文词或相当长度的中文；不要用连续书摘代替解释。

外文引文可保留原文并给出简短自译。不要把自译伪装成某个已出版中译本。

### 观点概括模式

没有可访问原文时：

- 只写能够高置信确认的核心观点；
- 明确说明本次未逐页核对原书；
- 不使用引号；
- 不提供猜测的页码或章节；
- 遇到不确定的观点就删除或继续检索，不用模糊措辞掩盖。

## 5. 四项内部检查

每个准备写入回答的核心观点都要通过：

1. **书内支撑**：它是作者稳定的思想，而不是孤立句子；
2. **问题解释力**：它确实改变了对用户问题的理解；
3. **非通用常识**：它保留了这本书独特的概念、推理或视角。
4. **处境贴合**：面对具体经历时，它能够回应一个真实矛盾、限制或选择，而不是只提供正确但泛化的道理。

不通过的内容不要写入，即使听起来正确。

## 6. 保持书籍独立

完成一本书的提取后再处理下一本。不要先想一个自己的答案，再到三本书中寻找佐证。

在所有书籍回答完成前，不做统一总结。允许它们：

- 给出不同答案；
- 使用不同的问题定义；
- 在某些地方互相冲突；
- 留下无法调和的分歧。

最后只制作“道路地图”：每本书把问题带向哪里。不要把不同答案压成最低公分母。
