## 1. 一句话本质

**不用任何视频生成模型。** 每一帧都是 Claude 写的网页（Canvas 2D / WebGL / three.js）画出来的，音乐用免费采样库编曲，旁白用 TTS，最后 ffmpeg 合成。卖点是「每一帧画面、每一个音符、每一刀剪辑都是代码做的」。

## 2. 技术管线

```
timeline.js（唯一时间源）
 ├─ 画面：index.html 暴露 window.render(t) → 无头 Chrome 逐帧截图 → video.mp4
 ├─ 旁白：TTS 每句一个 wav → faster-whisper 回听校验 → 词级时间戳
 ├─ 音乐：同一时间轴生成乐谱（采样器 + 合成）→ 分轨
 ├─ 音效：按 window.EV 事件点程序化合成拟音
 └─ 字幕：.srt + 烧进画面的风格化字幕
混音（压缩、ducking、配平）→ mux.sh 两遍 loudnorm −14 LUFS → film.mp4
```

关键设计：

- **画面是时间的纯函数。** 页面只需要 `window.DUR`、`window.render(t)`、`window.READY`，可选 `window.EV`（音效事件）和 `window.TEXTS(t)`（可读性检查）。禁止 `Date.now()`、禁止无种子的 `Math.random()`（`core/lib.js` 提供 `mulberry` 和 `hash`），也不许跨帧保留状态。所以任意一帧都能单独渲染，可以多 worker 并行。
- **渲染器**（`core/render/video.mjs`）：Playwright 起无头 Chromium，每个 worker 一个浏览器，`render(f/FPS)` 之后截 JPEG（q95），经管道交给 ffmpeg 编成分段，最后用 concat 无损拼接。另外有锁文件和崩溃清理。
- **颗粒感在 ffmpeg 里加，不在页面里画。** 画进页面的颗粒会让每帧都难以压缩，也会拖慢渲染。
- **一个时间轴驱动一切。** `SECS`（段落 / bpm / 拍数）和 `HIT`（关键动作落在第几拍）导出成 JSON，乐谱、混音、字幕、检查脚本共用。`cuecheck.py` 校验画面卡点和音乐 cue 的误差，目标是 0 ms。
- **声音：**
  - 采样器 `sampler.py` 调用 VSCO 2 CE、VCSL、FreePats、Karoryfer、Salamander 这些免费乐器库，带轮换采样，避免机关枪感。
  - `pluck.py` 用 Karplus–Strong 物理建模做古琴、琵琶、三味线。
  - 音效 `sfx.py` 全部程序化合成（点击、呼啸、纸张、底噪……）。
  - 旁白：英文用 Kokoro（本地），中文用 edge-tts（微软神经语音，需联网）。每句都用 whisper 转写回来逐字比对，不对就重新生成。
  - 混音：人声先压缩，再按 RMS 配平，人声比音乐高约 10 dB。低频 20–120 Hz 控制在 −3 dB 左右。
- **3D**：three.js r170，物理景深 + GTAO，2 倍分辨率渲染后降采样，低强度 Poly Haven HDRI 打光。
- **角色**：2.5D 骨骼每帧求解。连肩膀旋转顺序都写成了规则（先外展后前屈，否则举手会交叉成 X）。

## 3. 「风格」是怎么被编码的：STYLE.md 的 11 节

每种风格一个 `STYLE.md`，结构固定：

1. Essence（本质，以及「它不是什么」）
2. Materials & rendering（材质和渲染方式）
3. Colour logic（用色逻辑）
4. Type & subtitles（字体和字幕）
5. Motion quality（运动质感）
6. Camera grammar（镜头语法）
7. Sound palette（声音调色板）
8. Native moves（这个媒介独有的招式）
9. Pitfalls（这个媒介的坑，以及解法）
10. Engine（对应的引擎代码）
11. Variation space（可以自由发挥的部分）

以水墨为例：
- 本质写的是「留白是空间，一笔就是一座山」，并明确「不是水彩，不是加了笔刷纹理的矢量图」。
- 招式写了「飞白从静默里冲出来」「墨晕转场」「手卷横移」。
- 坑写了「干笔看起来像虚线 → 用长尺度噪声 + 沿笔画递减的含墨量」。

**核心思路：风格不变，故事全放开。** STYLE.md 是不能动的约束，故事、结构、角色、镜头都由 agent 根据用户的题材来决定。样片只用来学技术，明确禁止抄样片的故事。

## 4. 导演方法论（DIRECTOR.md，整个项目最值钱的部分）

评判顺序是：**声音 > 节奏 > 镜头 > 表演**。好看的画面只是起点。

- **故事**：一个主体、一个目标、一个转折。前 3 秒必须有钩子，结尾要呼应开头。全片一个「媒介原生招式」，放在情绪最高点。
- **先找对标**：动手前选 1–2 部参考作品，写清楚「学什么 / 不学什么」。
- **写 Treatment**：先列 3 种候选结构再选一个；然后写镜头表（景别、角度、运镜、时长、**为什么这么拍**）、逐秒节拍、cue map、声音设计表。
- **声音**：
  - 每个可见动作都要有声音。
  - 分三层：环境、拟音、音乐。
  - 至少两次真正的静默，静默之后的第一个声音要是全片最重要的声音之一。
  - 至少两次用 J-cut / L-cut 做声音转场。
- **节奏**：先写音乐网格，再做动画。必须有快慢交替，必须有一次明显的加速或减速和一次喘息。
- **阅读时长有公式**：
  - 字幕至少停 1.8 s，并且不短于台词时长 + 0.6 s。
  - 中文文字入场后停留 字数 ÷ 4.5 + 1.5 秒，英文是 字母数 ÷ 15 + 1.5 秒。
  - 标题卡至少停 4 s。
  - 这些由 `readcheck.mjs` 自动检查。
- **镜头**：至少 4 种运镜，一个让人记住的招牌镜头。转场在媒介内部完成，不用默认的淡入淡出。
- **防止抄样片**：对比结构、开场、招牌镜头、镜头路径、配乐形状、结尾这 6 项，至少 4 项要和样片不同。
- **交付前自检**：每 1–2 秒抽一帧拼成接触表看两遍；关键动作按 0.2 s 抽帧；跑 ebur128 测响度、blackdetect 查黑帧，再用 whisper 回听一遍；最后带声音全速看一遍。

## 5. 10-19 新功能：改成你自己的风格（MY-STYLES.md）

推文对应的就是这个更新：

1. 选一个基础风格（只能选一个；想混两种，就以本质更接近的那个为底，另一个只当改动来源）。
2. agent 读完 STYLE.md，把可以改的地方分成三组告诉用户：
   - **放心改**：配色、字体、运动节奏、声音、原生招式。
   - **会改变性格**：材质和渲染、用色逻辑本身、镜头语法。agent 要说清楚每改一项会失去什么。
   - **不能改**：本质和引擎。改了就是另一个风格，agent 会建议换一个更接近的底子。
3. 一轮最多改 5 处，写进 `~/lemo-my-styles/<slug>/`，包括完整的 `STYLE.md`、`style.json`（记录基于哪个库版本）和 `CHANGES.md`（逐行写清：哪一节、原来是什么、现在是什么、为什么改）。
4. 先出一张风格帧，和原风格并排对比，**等用户确认**。
5. 再出一支 15–30 秒测试片：每一处改动至少出镜一次，原生招式出现一次。交付时告诉用户每处改动在第几秒能看到。

存放在库外，所以 `git pull` 和卸载都不会动到用户自己的风格。

## 6. Agent 协作设计的巧思

- **只问一轮问题**：一条消息问完（事实、自有素材、语言、要不要先看分镜、缺哪些依赖），之后不再追问，空着的地方用合理的默认值补上。
- **依赖分层安装**：core 约 350 MB；voice 和 music 只在需要时才装。
- **出错要响**：页面 JS 报错或脚本 404 立即退出，避免产出坏片。
- **用户的片子不留作者水印**：交付前 grep 一遍，确认没有 "LemoLab / Opus 5.5" 字样。
- 署名和版权规则写成了硬性条款，素材只用 CC0 / CC BY / OFL，统一记进 CREDITS。

## 7. 增长打法（从 README 倒推）

- **用奇观作品引流**：OPUSCAR 98 让一个 Clawd 走过 98 部奥斯卡最佳影片，每部换一种画风，片长 6 分 31 秒，98 种风格提示词全部公开（附 JSON）。
- **高频、带日期的更新**：10-16 加了「实证影像」8 种风格，10-19 加了「改成你自己的风格」。每次都配一条推文和一支片子。
- **按 star 里程碑发感谢短片**：300 星《The Lamplighter》18 s，800 星《Reverse Shot》39 s，2000 星《Refresh》50 s。这些感谢片本身也在展示产品能力。
- 中英双语 README，加上 `claude plugin install` 一行命令安装，图库站为每种风格放一支样片。
- 「这不是 awesome 合集，所有片子都是我自己做的」：靠作品证明，和资源汇总类仓库拉开距离。

## 8. 我的结论 / 可借鉴点

1. **护城河不在代码，在于把品味写成可检查的规则。** 阅读时长公式、静默次数、运镜种类、「和样片至少 4/6 项不同」，都是把主观审美变成 agent 能自检的指标。
2. **用约束换可控性。** 不用视频模型，换来的是确定性（任意帧可复现、可并行）、可编辑性，以及干净的版权。
3. **「固定约束 + 开放变量」的提示词结构很通用。** STYLE.md 这 11 节可以直接套到任何品牌或内容规范上：本质 / 不是什么 / 招式 / 坑 / 自由空间。
4. **自定义的流程也值得学**：先分成「放心改 / 会变味 / 不能改」三组，一轮最多 5 处，先出风格帧，等确认后再出测试片。这是一个很好的人机协作节奏。
5. 对内容工作的直接用法：「产品拆解 Exploded Teardown」「数据叙事」「工程简报板」这几种风格，天然适合做车型亮点、技术讲解和销量战报的短片。
